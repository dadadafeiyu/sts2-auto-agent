# 哦鲸鲸爬塔 2（StS2 Auto Agent）

让 **AI 自己打《杀戮尖塔 2》** 的一套东西：

- **模组**（C#，装在游戏里）：把每一处「需要玩家决定」的地方变成结构化数据，交给 AI；再把 AI 的选择执行回游戏。
- **决策服务**（Node.js，跑在本地）：把模组的请求转成一次模型调用，返回一个 JSON。

**没有硬编码策略**——出牌、选牌、路线、商店、营火、事件，全部由模型决定。

---

## 它现在能做什么

| 场景 | 谁决定 |
|---|---|
| 战斗出牌 / 目标 / 结束回合 | 模型 |
| 卡牌奖励、商店、事件、营火、宝箱 | 模型 |
| 选牌（锻造/附魔/删除/变形/弃牌） | 模型 |
| 地图路线 | 模型（带路线评分辅助） |
| 喝药水 / 丢药水 | ⚠️ 未跑通（见「还没做」第 2 条） |
| 开局（选角色 / 继续存档） | 模型或本地配置 |

**给模型的不是截图，而是结构化事实**：卡牌伤害/格挡（**游戏自己算的**）、费用（含临时增减）、敌人意图（含力量/虚弱/易伤修正）、毒伤预告、双方 buff、手牌是否发完。

## 目录

```
mod/            模组源码 + 通用编译脚本（自动找游戏目录）
mod-assets/     知识库（卡牌/遗物/药水/能力数据 + 评分表）
decider/        决策服务（本地 HTTP，默认端口 18731）
integrations/   可选集成（QQ 播报等）
```

## 三步安装

```powershell
# 1. 编译并安装模组（自动找游戏目录，找不到会让你指定）
powershell -File mod\build.ps1 -Install

# 2. 起决策服务（需要 Node 18+）
node decider\index.js

# 3. 开游戏 → 进入战斗 → 模组开始工作
```

> 详细步骤、验证方法、常见错误：见 **[INSTALL.md](INSTALL.md)**（这份文档是写给 AI 看的，直接丢给它就能装）。
>
> 想知道**它是怎么实现的**（为什么数值都由游戏算、选牌怎么接管、payload 长什么样）：见 **[ARCHITECTURE.md](ARCHITECTURE.md)**。

## 关于知识库

`mod-assets/knowledge/` 里的东西分两类：

| 类型 | 文件 | 说明 |
|---|---|---|
| **游戏数据** | `cards.json` `relics.json` `potions.json` `powers.json` `events.json` `cards.index.tsv` | 从游戏导出，版本更新后可用模组内置的导出器重新生成 |
| **评分表** | `scores.tsv` `relic_scores.tsv` `route-rules.tsv` `sandpit.tsv` | **作者按自己理解调的，不是官方数据** |

**想改成自己的口味**：直接编辑 `scores.tsv`，模组会热重载（不用重编译）。

格式：

```
id<TAB>char<TAB>score<TAB>tier<TAB>up<TAB>upType<TAB>kw
CARD.NEUTRALIZE	silent	65	B	85	T1-翻倍	
```

- `score`：这张牌本身值多少分（1~100）
- `up`：升级收益分（锻造时用它排序）
- 重复抓同一张牌会扣分（1 张 -6 / 2 张 -14 / 3 张以上 -26，毒牌更狠）

## 已知限制

> ⚠️ **依赖游戏内置 AutoSlay 的私有实现**（Harmony patch `PlayRunAsync`）。
> 游戏更新后可能失效，失效表现：日志出现「找不到 PlayRunAsync」。

其他：

- 只支持单机单人
- 需要 Windows + .NET Framework 4.x（编译用系统自带 `csc.exe`）
- 决策服务优先用宿主的模型调用；没有宿主时自动用自带 shim（OpenAI 兼容接口，填 `STS2_LLM_API_KEY` 即可）

## 数据与日志位置

默认都在 `%APPDATA%\Sts2Agent\`：

```
%APPDATA%\Sts2Agent\
├── logs\              模组日志（排查问题看这里）
├── shots\             结算截图
├── memory\            局末记忆（对战总结）
├── autoplay.flag      让模组进入"自己玩"模式
└── config.json        可选：改路径/端口
```

`config.json` 示例见 `mod-assets/config.example.json`。

## 还没做 / 只做了一半

> 这份清单是给自己人看的，别当成"即将上线"。

### 1. Agent 反向调整知识库（自我学习）

**现状**：知识库是**只读**的——AI 只能读分数，不能改。

**想做的**：

```
一局结束后，AI 复盘时如果发现"这张牌我评 65 分，但实际它让我输了"
   → 它自己写一条修正建议
   → 落到 scores.tsv（或单独的调整表）
   → 下一局生效
```

**要解决的**：

| 问题 | 说明 |
|---|---|
| 谁有权限改 | AI 改分可能越改越偏，需要人工确认或限幅 |
| 怎么防抖动 | 一局样本太小，应该累计 N 局才调一次 |
| 冲突合并 | 多人分享同一份 scores.tsv 时怎么办 |

**目前只实现了"读"和"热重载"**（改文件立刻生效），没有自动写。

---

### 2. 药水（**失败**，目前不可用）

代码写了三件事：

```
读药水槽 → 塞进战斗 payload
{"potion":索引,"t":目标}  → UsePotionAction 入队
{"dropPotion":索引}       → PotionCmd.Discard
```

**实测结果是失败的**：读药水槽拿到的始终是空列表，所以 AI 完全看不到自己有什么药水，更不会用。

定位到的问题：

| 问题 | 说明 |
|---|---|
| `Player.PotionSlots` 读取方式 | 一开始当成"槽位对象"读（`slot.Potion`），实际它是 `IReadOnlyList<PotionModel>`，元素本身就是药水 |
| 修完仍未验证成功 | 改成直接读元素后编译通过，但后续测试里没再出现 `potions` 字段，**等于没跑通** |

**结论：药水这条路要重做**，不能算"已实现"。

---

### 3. 彻底摆脱 AutoSlay

**现状**：房间推进、界面点击、战斗循环仍然依赖游戏内置 AutoSlay。
我们只在"决策点"上接管（选牌/出牌/选项/路线），**"什么时候做什么"还是它决定的**。

**后果**：

- 游戏更新改 AutoSlay → 本模组直接失效
- AutoSlay 内部超时（我们已放宽到 30 分钟，但治标）

**想过自己写主循环**（状态机 + 自己分派房间/界面），试过一版，卡在"读不到事件房节点"，暂缓。
